# 健康信息产品设计方案（MVP + 可扩展）


## 1. 背景与目标
- 目标：本健康模块是“主动式 AI 助手”的情境感知通道之一，不做独立健康 App，而是为 AI 主动理解用户状态、生成更贴合的建议与提醒服务。
- 原则：
  - 数据以时间戳为唯一时序基准，便于趋势分析与跨源对齐。
  - 最小可行 + 快速闭环（2周MVP），同时预留可扩展到本地 BLE 网关与厂商云的空间。
  - 隐私优先、用户可控（授权可撤回、可导出/删除）。
  - 与桌面识别链路协同：当 `pkg/screenshot/quality/` 识别长时间工作/应用态变化时，结合健康状态触发更合适的主动提示。

## 2. 用户与身份模型（多用户场景）
- 绑定方式：手机号用作账号标识与登录入口，支持一个手机号多设备、多数据源。
- 标识关系：`user_id` ←→ 手机号（唯一）；设备以 `device_id` 区分；数据源标注 `source`（healthkit/fit/ble/...）。
- 会话关联：长连接/对话上下文均带 `user_id`，AI 取用最近时间戳的健康状态作为对话上下文片段。
- 权限边界：每个用户的健康数据严格隔离；共享仅在用户授权的前提下（不作为MVP目标）。

## 3. 产品形态与范围
- 形态A（MVP，2周）手机 App 伴侣：
  - 账号/手机号绑定，HealthKit/Google Fit 等生态授权。
  - 数据上报后端（Golang+xorm），今日面板 + 7/30天趋势。
  - 任务与提醒（结合三天运动循环）。
  - AI 对话入口与建议卡片。
- 定位澄清：本模块的 UI 是 AI 建议与提醒的“承载面板”，核心价值在于为主动式 AI 提供“健康上下文”，非追求完整健康工具集。
- 形态B（3~6周并行）本地 BLE 网关小盒子：
  - 直连体脂秤/血压计，离线缓存，局域网/TLS上传。
  - 更强隐私与稳定性，可本地语音/LED提醒。
- 形态C（后续）厂商云 API 对接：
  - 华为/小米/Withings/Omron 等，扩大设备覆盖。

## 4. 数据来源与优先级
- 首批指标（必做）：体重/体脂、血压、步数、心率、睡眠。
- 第二批（增强）：血糖（手动/拍照OCR→后续CGM云）、围度、体温。
- 数据源：
  - 手机平台：iOS HealthKit、Android Health Connect/Google Fit（国内评估华为/小米健康云）。
  - 直连硬件（B形态）：通用 BLE 协议体脂秤、上臂式血压计。

## 5. 信息架构（App）
- 首页：今日任务卡（称重/测压/运动）、异常提醒、AI 建议。
- 数据：多指标时间轴与趋势（按日/周/月切换）。
- 任务：个性化打卡 + 目标（结合三天运动循环）。
- 对话：与 AI 助手对话，引用最近健康数据（按时间戳）。
- 我的：手机号与账号绑定、健康授权管理、设备管理、隐私设置、数据导出/删除。

## 6. 关键用户流程（示意）
1) 首登绑定：手机号登录 → 选择数据源 → 授权 HealthKit/Google Fit。
2) 首次同步：拉取最近90天核心指标 → 上报后端 → 生成初始趋势。
3) 每日使用：
   - 早称重、晚测压 → 自动/手动上报。
   - 运动提醒 & 打卡（第1天跑步1h/第2天走路1h/第3天有氧20min）。
   - 晚间睡眠数据第二天回填。
4) AI 建议：异常提醒（如高压>140/90），结合饮食与运动习惯给行动点；当桌面识别为“高强度专注/长时间坐姿”时，参考当日步数/心率/血压状态调整提示语与紧迫度。

## 7. 数据模型与端云契约（时间戳）
- 共性字段：`user_id`、`device_id`、`source`（healthkit/fit/ble/...）、`ts`(int64)、`raw`(JSON)。
- weight：`weight_kg`、`body_fat_pct`、`bmi`。
- bp：`sys`、`dia`、`hr`。
- bg（第二批）：`glucose_mgdl`、`context`(fasting/postprandial)、`note`。
- activity：`steps`、`calories`、`hr_avg`、`hrv`。
- sleep：`duration_s`、`stages`(JSON)。
- 幂等与去重：`(source + external_id)` 或 `(ts + value_hash)`。
- 延迟到达：允许回溯写入，重算当日统计。

## 8. 隐私与合规
- 最小化权限：按指标细分授权，可随时撤回；可视化授权状态。
- 数据主权：数据导出/删除；离线模式（B形态）。
- 安全：TLS 传输；Token 含设备编号与时间戳；存储脱敏、操作审计。
- 红线：不采集敏感内容（通讯录/相册等），仅健康指标与必要元数据。

## 9. 架构与接口
- 客户端（iOS/Android）：
  - HealthKit/Health Connect/Google Fit 读取 → 标准化 → 上报 API。
  - 失败重试、增量同步、网络切换处理。
- 后端（复用当前项目）：
  - API 层：`/api/health/report`、`/api/health/query`、`/api/health/tasks`。
  - 存储：xorm 建表（时间戳），与现有 `model/` 目录风格一致。
  - 消息：异常事件推送到长连接（参考 `internal/connection/`）。
  - AI：
    - 上下文融合层：`internal/ai/` 消费健康最新状态（过去N小时/天的聚合）+ 桌面识别上下文，形成“健康态摘要”。
    - 提示词注入：`internal/prompt/` 在生成建议/对话时带上健康态摘要与触发原因（例：久坐+未达步数目标）。
- 与桌面识别联动：
  - 在 `pkg/screenshot/quality/` 基础上，健康相关提示优先级提升（例如久坐提醒与运动打卡）。

### 10.1 主动式 AI 触发器与对话注入
- 触发来源：
  - 健康事件：高压≥140/90；当日步数<阈值；睡眠不足；体重连续上行。
  - 桌面事件：长时间坐姿/深色IDE前台/视频窗口长驻；任务完成/上下班时间。
- 触发规则（示例）：
  - 如果“桌面久坐 ≥ 50 分钟”且“当日步数 < 4000”，触发“起身活动5分钟”并给到轻量运动建议（对齐三天循环日程）。
  - 如果“血压高压≥160/100”，触发强提醒并建议复测；若桌面识别为“视频/游戏”，语气与文案更温和，避免打断焦虑。
- 对话注入：
  - 在与用户聊天时，将“最近健康态摘要（时间戳）+ 触发原因”作为系统上下文片段嵌入，不曝光原始隐私数据。
  - 所有引用均以时间戳为准，明确“最近一次有效值”的时间与来源。

## 10. 任务与提醒（产品规则）
- 每日固定：
  - 早 06:30-10:00：称重（无数据→提醒）。
  - 晚 19:00-22:30：血压（无数据→提醒）。
- 运动循环：
  - 第1天：室内慢跑 60 分钟。
  - 第2天：室内慢走 60 分钟。
  - 第3天：有氧全身 20 分钟。
- 晚间建议：若睡眠不足或当天活动量低，第二天适当下调运动强度。
- 灵活性：用户可配置提醒窗口与强度（保守/标准/强烈）。

## 11. 看板与报告
- 今日面板：最新体重/体脂、血压、步数、心率、睡眠（上次有效 ts）。
- 趋势：7/30天折线/柱状，标注异常点与关键事件（饮食/运动打卡）。
- 报告：日/周卡片，行动建议 3 条以内，便于执行。

## 12. MVP 范围与排期（2周）
- 第1周：
  - 账号与手机号绑定；HealthKit/Google Fit 授权。
  - 体重/体脂、血压、步数、心率、睡眠入库；今日面板与基础趋势。
  - 每日任务与提醒（结合三天循环）。
- 第2周：
  - AI 建议卡片与对话联动（引用时间戳数据）。
  - 血糖手动/OCR补录；数据导出/删除；隐私设置完善。

## 13. BLE 网关 PoC（并行 3~6 周）
- 硬件：Raspberry Pi 5 或 RK3588；Wi‑Fi/以太网；LED 指示。
- 设备：通用 BLE 体脂秤 + 上臂式血压计各 1 款。
- 流程：BLE 采集 → 本地标准化 → 环形缓冲 → 批量 TLS 上传。
- 本地隐私：可选“离线仅看板、不上传云端”模式。

## 14. 指标与埋点
- 授权转化率、日活、数据到达率、任务完成率、7日/30日留存。
- 异常率：高压/高心率触发数、建议采纳率。
- 成本：云端分析调用次数、带宽开销（与截图通道合并统计）。

## 15. 风险与应对
- 平台差异：HealthKit/Health Connect/厂商云数据口径不同 → 建立标准化映射与兼容层。
- 授权意愿：仅在必要时请求权限，解释价值，支持“只读部分指标”。
- 数据延迟：睡眠等指标次日回填 → 前端标识“估算/回填”。
- 隐私合规：默认最小化采集、可撤回、导出/删除、审计日志。

## 16. 与现有代码的集成点（仓库内）
- 后端服务：
  - 模型与存储：`model/`（新增 health_* 模型，xorm）
  - 路由：`router/`（新增 health 模块路由）
  - 服务：`service/`（健康数据入库、查询、任务生成）
  - 公共：`global/`, `initialize/`（配置与初始化）
- 桌面截图质量筛选：`pkg/screenshot/quality/`（健康提醒策略可复用埋点体系）
- AI 建议：`internal/ai/` 与 `internal/prompt/`

## 17. 后续迭代方向
- 厂商云生态接入（华为/小米/Withings/Omron）。
- 连续血糖（CGM）数据适配与低糖餐建议。
- 个性化目标与奖励体系（分层提醒强度）。
- 本地推理：体征异常本地先告警，云端做深度解释。

## 18. MVP 生态与权限清单（理想范围）
- iOS（首发优先）：
  - 框架：HealthKit
  - 权限（读取）：体重、体脂、身高、心率、步数、活动能量、静息能量、睡眠分析、血压（收缩/舒张）
  - 首次授权弹窗逐类请求，提供“为何需要”的解释；设置页可随时撤回
- Android：
  - 框架：Health Connect（优先）或 Google Fit
  - 权限（读取）：体重、体脂、心率、步数、活动、睡眠、血压
  - 国内生态（备选）：华为/小米健康云（需商务与审核）

## 19. 端云接口契约（示例）
- 通用请求头：
  - Authorization: Bearer <token(含设备编号与签名)>
  - X-Client-Ts: <int64>
- 上报接口：`POST /api/health/report`
```json
{
  "user_id": "u_123",
  "source": "healthkit", 
  "device_id": "iphone_15_pro_max",
  "metrics": [
    {
      "type": "weight",
      "ts": 1724131200,
      "payload": {"weight_kg": 76.6, "body_fat_pct": 24.1, "bmi": 28.1},
      "external_id": "hk_abc123",
      "raw": {"hk_unit": "kg"}
    },
    {
      "type": "bp",
      "ts": 1724167200,
      "payload": {"sys": 132, "dia": 86, "hr": 72},
      "external_id": "hk_bp456",
      "raw": {}
    }
  ]
}
```
- 响应：`{"ok":true, "dedup":1}`（去重条数）
- 查询接口：`GET /api/health/query?user_id=u_123&type=weight&from=1723500000&to=1724300000&limit=500`
- 任务接口：`GET /api/health/tasks?user_id=u_123`（返回今日任务与状态）
- 异常订阅：长连接消息 `topic=health.alert`（血压超阈、心率异常等）

幂等策略：优先 `(source + external_id)`；无 external_id 时使用 `(type + ts + hash(payload))`。

## 20. 指标映射与标准化
- 体重/体脂：单位统一为 kg / %；缺省身高时仅显示体重与体脂，BMI 延后计算
- 血压：单位统一 mmHg；若仅收缩压存在，标注为“单值上报”
- 心率：bpm；活动/静息通过平台标签或阈值推断
- 步数与能量：整天聚合与分时段明细并存（查询可按日/小时）
- 睡眠：统一拆分为 awake/light/deep/rem（若来源不含分期，仅给 duration_s 与 source=estimated）

## 21. 授权与隐私 UX 流程
- 首次进入：
  1) 绑定手机号与账号
  2) 解释价值页（为何要读取哪些指标）
  3) 分步授权（体重/血压/活动/睡眠），每步可“仅此一次/以后提醒/拒绝”
- 设置页：
  - 授权状态列表（可撤回）
  - 数据导出（CSV/JSON，时间戳）与删除
  - 离线模式开关（不上传，仅在本机可见）
- 法务：隐私政策与用户协议，记录同意时间戳与版本

## 22. 提醒与任务规则（细化）
- 固定提醒：
  - 称重：06:30-10:00，未上报触发一次通知；连续3日缺失给出“如何坚持”建议
  - 血压：19:00-22:30，未上报触发一次通知；如两周内高压均值>135，周报中提示复测
- 运动循环：
  - 第1天：慢跑60min；第2天：慢走60min；第3天：有氧20min；循环
  - 当日活动低于门限（如步数<4000）时，次日建议保持轻量强度
- 异常：
  - 血压阈值：≥140/90 提醒；≥160/100 强提醒并建议复测或咨询
  - 心率异常：静息>100 或 <45（非运动时）提示检查
  - 睡眠<6h 且连续2日，建议适度下调运动强度
- 用户可配置提醒强度（保守/标准/强烈）与时间窗口

## 23. 设备适配矩阵（优先级）
- 体脂秤：通用 BLE 协议优先（Mi/Fitdays 等常见方案）；平台生态可先同步
- 血压计：上臂式 BLE（Omron/爱奥乐等），优先校准稳定性
- 手表：Apple Watch / 华为 / 小米 → 通过各自生态平台拉取
- 第二批：血糖（手动/OCR→CGM 云），围度/体温（可选）

## 24. BLE 网关 PoC 细节
- 硬件与系统：
  - 计算平台：Raspberry Pi 5（优先）或 RK3588 盒子；MicroSD/EMMC 32GB+；2.4/5G Wi‑Fi 与以太网
  - 系统：Ubuntu Server / Debian；Docker 可选
  - 外设：状态 LED（RGB）、蜂鸣器（可选）、按钮（隐私/上传开关）
- BLE 适配：
  - 协议：GATT，支持典型体脂秤服务/特征（重量、体脂、阻抗、序列号）、血压服务/特征（收缩/舒张/心率）
  - 扫描策略：开机10秒快速扫描→停止；失败退避（指数回退，最大5分钟）
  - 绑定：按品牌白名单 + MAC 记忆；支持多设备并行连接（体脂秤/血压计）
  - 校验：读设备时间/序列；必要时本地对时，标注 `ts_src=local` 或 `device`
- 标准化与缓存：
  - 标准化模型同第7节；附 `source=ble-gw`、`device_meta`（brand/model/mac/fw）
  - 环形缓冲：内存与本地KV（如 SQLite/Badger）双写；容量7天或1万条上限
  - 幂等键：`device_id + external_seq` 或 `type + ts + hash(payload)`
- 上传与协议：
  - 触发：连网即批量；按批次（<=100条）上传；错误退避（30s→5min）
  - 传输：TLS；鉴权 Token 含时间戳与设备编号；支持断点续传（返回 last_ack）
  - QoS：带宽限制（如 100KB/s）；夜间模式（22:30-07:30 仅关键事件）
- 安全与隐私：
  - 隐私按钮：开启“本地模式”→仅缓存不上传；LED 呼吸蓝显示
  - 数据加密落盘（可选）；日志脱敏（屏蔽MAC后3字节）
  - Web 面板（可选）：局域网只读看板（密码保护），显示最近数据与状态
- 本地告警：
  - 阈值本地校验（高压≥160/100、极端心率等）；LED红闪+蜂鸣2秒（可关闭）
  - 告警同时排队上报（网络可用即传）
- 运维与升级：
  - 远程配置下发（白名单设备、阈值、上传窗口）；OTA（容器镜像/二进制）
  - 日志分级与采样；设备健康心跳（温度、CPU、空间）
- 联调计划：
  1) 第1周：接入1款体脂秤 + 1款血压计，完成扫描、配对、读数与本地缓存
  2) 第2周：打通上传、幂等去重、异常告警、LED 状态；小范围试用
  3) 第3~4周：稳定性与兼容性测试（断电、断网、重连、多设备切换）

## 25. 验收标准（MVP）
- 账号/手机号绑定成功率 ≥ 98%
- 授权引导完成率 ≥ 85%，数据首日到达率 ≥ 80%
- 指标到达率（日活用户）：体重≥60%，血压≥50%，步数/心率≥80%，睡眠≥70%
- 日志与审计：100%关键操作记录（授权、导出、删除）
- AI 建议卡片：日均CTR ≥ 15%，建议采纳反馈率 ≥ 20%

## 26. 埋点与监控（落地）
- 埋点：授权漏斗（查看→同意→到达）、上报成功/失败、任务完成率、提醒触达率
- 监控：接口P95、上传错误码分布、端侧重试次数、数据延迟分布
- 成本面板：端云数据量、分析调用次数（与截图通道合并统计）

## 27. 时间线（理想）
- 第1周：账号/授权、数据入库（体重/体脂、血压、步数/心率、睡眠）、今日面板、基础趋势、提醒
- 第2周：AI 建议联动、血糖手动/OCR、隐私（导出/删除）、周报
- 第3~6周（并行）：BLE 网关 PoC（体脂秤+血压计），验证离线与隐私闭环
