# RobotChatAny 项目需求与方案全景梳理（2026Q2）

> 文档目的：基于仓库现有代码与 `doc/` 历史方案，沉淀一份可用于“继续开发/对外沟通/团队协同”的统一项目说明。  
> 文档范围：需求背景、目标与边界、总体方案、模块拆解、当前状态评估、主要问题与后续路线。  
> 版本：v1.0（整理稿）

---

## 1. 项目一句话定义

RobotChatAny 是一个“主动式多模态 AI 助手”系统：通过时间、位置、视觉、对话与健康等信号，做低打扰的情境判断，在合适时机主动给出提醒、建议与对话。

---

## 2. 需求背景（Why）

### 2.1 用户痛点
- 信息过载与任务切换频繁，用户容易被无效提醒打断。
- 传统聊天机器人“被动等待提问”，无法在关键时刻主动提供帮助。
- 单一模态（只看聊天文本）难以理解真实场景，建议不够贴合。

### 2.2 产品机会
- 通过多模态上下文（位置/天气/屏幕行为/历史对话/健康状态）提升“理解用户当下状态”的能力。
- 用“限频 + 冷却 + 夜间勿扰”策略降低打扰成本，让主动提醒更可接受。
- 构建“长期记忆 + 画像 + 触发策略”闭环，提高建议命中率和用户黏性。

### 2.3 目标用户（当前定义）
- C 端优先：个人效率与陪伴需求用户（专注、会议、出行、健康等场景）。
- 后续可扩展：企业客服/教育/健康管理等垂直方向。

---

## 3. 产品目标与非目标

### 3.1 产品目标（当前阶段）
- 实现“可用”的主动对话与提醒能力（不是只会被动问答）。
- 形成可扩展的多模态感知与决策骨架（Awareness + Brain + Trigger + Prompt）。
- 打通实时通信链路（TCP 长连）与系统管理链路（Gin API）。
- 保证基础安全、稳定性与成本可控。

### 3.2 非目标（当前版本）
- 不追求一次性做成全功能健康 App 或完整语音硬件生态。
- 不追求重资产视频/音频云实时处理全量上线。
- 不追求复杂多租户企业级权限体系（先做单用户/轻多用户可演进）。

## 4. 典型业务场景（What）

### 4.1 工作专注
- 信号：工作时段 + 办公相关地点 + 屏幕行为（可选）。
- 动作：建议 25 分钟专注、列今日三件事、减少干扰。

### 4.2 会议纪要与跟进
- 信号：会议类窗口/关键词/上下文事件。
- 动作：会后纪要草稿、跟进待办建议。

### 4.3 出行天气提醒
- 信号：天气突变 + 通勤时段/位移趋势。
- 动作：带伞加衣、路线/打车建议、替代地点建议。

### 4.4 健康友好提示（轻干预）
- 信号：久坐、步数不足、血压/心率/睡眠异常（后续增强）。
- 动作：低打扰提醒与可执行建议，不制造焦虑。

## 5. 总体方案设计（How）

## 5.1 架构分层
- 接入层：TCP 长连接（实时双向消息）+ Gin HTTP API（管理与业务接口）。
- 初始化层：`initialize/*` 串行装配配置、缓存、数据库、AI、触发器、队列、连接、TCP、NSQ 等组件。
- 感知层：`internal/awareness` 聚合位置、周边、天气、视觉占位信息。
- 决策层：`internal/brain` 维护世界状态（WorldState）、目标假设（GoalHypotheses）、Todo/Event/Task 等。
- 触发层：`internal/trigger` 管理时间/实时/行为/随机话题触发器。
- 提示词层：`internal/prompt` 负责 prompt 生成（当前以“人设+场景”模板为主）。
- 基础设施层：PostgreSQL、Redis、NSQ、对象存储（OBS/Minio/Local）等。

### 5.2 核心数据与状态模型
- WorldState：统一聚合 Profile/Health/Environment/Dialog/Todos/Events/GoalHypotheses。
- Awareness Context：位置转换、逆地理、周边、天气、视觉摘要（可空）。
- Trigger Config：可配置触发规则 + 历史抑制机制（防重复触发）。
- Screenshot Quality：本地图像质量评分与垃圾帧过滤，降低云分析成本。

### 5.3 决策范式
- “规则先行 + 大模型补充”：
  - 先由触发规则/轻量推断决定是否值得打断用户。
  - 再由 Prompt/LLM 生成更自然、可执行的话术与建议。
- 低打扰机制：
  - 每日上限、同类冷却、夜间勿扰、偏好学习。

## 6. 技术实现现状（代码对齐）

### 6.1 已落地主干（可运行骨架）
- 启动与装配：`cmd/main.go` + `initialize/*` 基本完善。
- 实时连接：`internal/tcp`、`internal/connection`、`internal/protocol` 已具备基础能力。
- Web 接口：Gin 路由体系已搭建（auth/user/system）。
- 感知模块：位置 + 高德能力（逆地理/天气/周边）已进入可用状态。
- 大脑模块：WorldState、GoalHypotheses、Todo/Event/Task/Health 等结构与方法已存在。
- 触发体系：触发器加载、随机选取、去重历史已实现。
- 截图质量：`pkg/screenshot/quality` 指标较完整，可用于前置过滤。

### 6.2 在途与占位（未完全闭环）
- 多模态云端理解链路（截图序列 + 聊天 + 长期记忆）仍以设计文档为主。
- 语音链路（VAD/ASR/TTS）与硬件 MQTT 方案尚未工程化合入主链路。
- 健康模块与 AI 主动策略联动仍处于产品方案/分阶段实施状态。
- 监控告警、SLO、策略评测看板尚未形成稳定工程闭环。

## 7. 方案亮点与设计价值

### 7.1 方向正确
- 从“被动问答”升级到“情境驱动主动服务”，产品方向明确。
- 文档与代码都强调“少打扰”和“隐私可控”，产品理念清晰。

### 7.2 工程可扩展
- 模块边界清楚：Awareness/Brain/Trigger/Prompt 分工明确。
- 支持逐步接入更多信号源（健康、语音、硬件、日历、热点）。

### 7.3 成本意识较强
- 截图质量筛选、本地缓存、TTL、批处理等思路成熟。
- 对“云调用成本”有明确估算与优化预案。

## 8. 关键问题与一致性风险（当前最需要处理）

### 8.1 时间戳单位不一致风险（高优先级）
- 多份文档写“统一毫秒(ms)”，但代码中大量使用 `time.Now().Unix()`（秒）。
- 不统一会导致：跨模块排序错误、TTL 误判、触发窗口错位、数据统计偏差。

### 8.2 模块间语义仍有“文档领先、实现滞后”
- 例如：多模态理解、健康联动、硬件语音链路在文档很完整，但主链路实现未完全打通。
- 需要明确“当前真实可交付能力”与“规划能力”，避免团队沟通偏差。

### 8.3 Prompt 与角色体系偏单一
- 当前 prompt 生成器仍偏“贴吧老哥”固定模板，难以支撑多场景产品化。
- 后续需要升级为“场景模板 + 用户画像 + 安全约束 + 任务目标”组合式提示词系统。

### 8.4 评测与运营闭环不足
- 触发效果、建议采纳、误打扰率等指标未形成稳定看板与自动调参流程。

## 9. 半年维度下的“技术热点与升级方向”（结合项目）

以下是结合你项目特点给出的“值得优先吸收”的方向，不是盲目追热点：

### 9.1 从“单次调用”升级到“代理式编排”
- 建议：把 Brain 侧流程改造成“任务分解 + 工具调用 + 结果校验”的可追踪链路。
- 价值：更稳的主动决策与可解释性，更方便做回放与复盘。

### 9.2 从“规则触发”升级到“规则 + 学习型策略”
- 建议：保留硬规则兜底，引入轻量学习排序（例如候选行动重排）。
- 价值：降低误触发，提升个体化命中率。

### 9.3 从“文本对话”升级到“多模态上下文统一总线”
- 建议：把截图/位置/健康/对话统一为标准事件模型（统一 ts、source、confidence）。
- 价值：减少模块拼接成本，方便新增感知源。

### 9.4 从“功能可用”升级到“可观测可治理”
- 建议：补齐事件埋点、策略看板、失败回放、灰度参数与回滚机制。
- 价值：让主动策略能持续迭代，而不是靠主观调参。

### 9.5 从“单模型依赖”升级到“分层模型策略”
- 建议：轻模型做筛选/分类，重模型做解释与生成；高成本链路只在高价值场景触发。
- 价值：显著降低成本，提高实时性与稳定性。

## 10. 建议的下一阶段路线图（务实版）

### Phase A（1~2 周）：先把“基础一致性”打牢
- 统一时间戳规范（建议全项目统一秒或毫秒，禁止混用）。
- 梳理触发策略配置项，形成单一配置源。
- 给核心链路补基础指标：触发次数、被抑制次数、用户反馈、调用成本。

### Phase B（2~4 周）：打通一个“可演示闭环”
- 选择一个主场景（推荐“工作专注”）做端到端闭环：
  - 感知输入 → Brain 判断 → Prompt 生成 → 主动提醒 → 反馈记录。
- 引入简单 A/B：不同话术、不同阈值、不同冷却策略。

### Phase C（4~8 周）：多模态与健康联动增强
- 接入截图序列理解最小版本（先单帧+摘要，再多帧）。
- 健康数据先做“弱耦合提示”，避免重医疗风险。
- 建立“建议采纳率/误打扰率/次日留存”的统一评估框架。

## 11. 对外沟通可用的项目定位（建议文案）

RobotChatAny 不是“会聊天的机器人”，而是“能理解你当下状态并在关键时刻提供帮助的主动助手系统”。  
它以多模态信号驱动，强调低打扰、可解释、可控隐私，并通过持续学习提升个体化建议质量。
